Research

SchemaShift: can open LLMs fix an existing SQL query after the schema changes? pilot results

Independent research · Oct 2026 – present · Python, SQLite, sqlglot, Ollama, Google Colab

Databases change: columns get renamed, tables are split, a "deleted" flag is added. A query written for the old schema then fails, or keeps running and silently returns wrong rows. I built 144 repair tasks from the BIRD Mini-Dev benchmark under four kinds of schema change, with gold answers computed automatically, and tested 9 open models (1.5B–16B parameters), each with and without a one-line hint.

Share of queries fixed when the same six columns get natural names (first_name → given_name) or meaningless ones (Attribute1), without a hint.

  • Silent errors go unnoticed. In 18 tasks the old query still runs but returns wrong rows after a soft-delete flag is added. Without a hint, no model fixed more than 4 of them.
  • Hints help general models, not SQL-specialised ones. Gemma 3 12B went from 0 to 15 of the 18; OmniSQL 7B stayed at 0.
